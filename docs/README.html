Forecasts inform. Constraints decide.

The Python application produces fresh 24-hour forecasts and constrained heat-allocation plans. It accounts for temperatures, shared equipment, storage, network losses, backup and community-service requirements.

The offline presentation uses saved outputs from that working backend. Its animated view does not train models or rerun the optimizer.

The two case studies are 111 8th Avenue, NYC and proposed Lake Hawkeye, Lansing, New York. The proposal conditionally favors NYC.

Try the live application's seasons, outages, prices, customer disconnection and source-temperature scenarios. Each selected date opens an independent 24-hour plan; the rolling backtest carries storage forward between actions.

Run it. Reproduce it.

Use Python 3.12 from the repository root. The saved models and dataset are included; serving the app does not retrain.

1. Set up

python -m venv .venv

# macOS / Linux: activate
source .venv/bin/activate

On Windows, no activation is needed: use .venv\Scripts\python.exe in place of python in the commands shown here.

2. Start the local app

python -m pip install -r requirements.txt
python run.py serve

Open http://127.0.0.1:8765. It binds only to this computer. Stop with Ctrl+C.

Keep the pinned versions for saved-estimator and solver compatibility.

Check the implementation

python run.py test
python verify_project.py
python -m ml.audit

These commands verify code and saved artifacts; they do not certify an installation.

Regenerate the evidence

python run.py data
python run.py train
python run.py backtest

Training regenerates detailed horizon/season metrics and test predictions omitted from this compact repository. These commands overwrite their model and result artifacts.

Annual model: python baseline/model/model.py. Read the dispatch/accounting guide and CSV ingestion contract for technical details.

Measure before building.

The 2.5 MW recovery tranche is an assumed thermal limit, not measured facility electricity. Heat-pump output includes compressor electricity; network losses and other electrical loads are separate. Geometry is schematic and customer cohorts are prospective.

The proposed design retains independent data-center cooling and customer backup. Source rights, measured loads, compatible demand, surveyed routes, vendor maps, tariffs, customer contracts, community consent and independent engineering review remain open. Tenant savings require enforceable pass-through.
